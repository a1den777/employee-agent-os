# FDE 现场交付手册

本手册说明如何使用 Employee Agent OS 完成一次真实的 Agent 部署。这里的 FDE 指 Forward Deployed Engineer（前向部署工程师）：在业务现场发现问题，并把问题做成可以被真实用户使用的端到端切片。

## 1. FDE 不交付一个“万能 Agent”

一次交付应该围绕一个具体工作流，而不是围绕一个抽象的“AI 助手”。先回答：

- 哪个员工在什么场景下遇到问题？
- 他现在如何完成这项工作？输入资料来自哪里？
- 哪一步最耗时、最容易错，或者最需要反复查找？
- Agent 可以辅助哪一步？哪些判断必须由人做？
- 什么结果算试点成功？失败时如何回退到原流程？

不要一开始承诺替换整个系统、自动化所有流程或取消人工审核。FDE 的第一版应当足够小，能够在真实现场验证价值。

## 2. Echo：摸清真实现场

Echo 不是把客户提出的功能原样记录下来，而是观察和追问：

1. 跟随一线员工完成一次完整任务。
2. 收集真实输入、输出、样例文件和例外情况。
3. 区分“必须准确”“可以建议”和“必须人工确认”的步骤。
4. 记录资料权限、敏感信息和外部副作用。
5. 与实际使用者确认验收标准，而不是只与管理者确认想法。

建议把调研结果整理为一个小型任务卡：

```text
任务：
使用者：
当前步骤：
输入资料：
期望输出：
高风险动作：
必须人工确认的节点：
失败回退：
验收标准：
```

## 3. Delta：端到端交付切片

将任务卡映射到仓库结构：

| 现场信息 | 框架位置 |
| --- | --- |
| 员工身份、职责、偏好 | `vault/members/<member-id>/member.md` |
| 公司事实、术语、政策 | `vault/company/` |
| 现场资料和待分析文件 | `vault/inbox/` |
| Agent 的上下文入口 | `agents/<member-id>/CLAUDE.md` |
| 可复用的执行方法 | `.claude/skills/` 或 `vault/skills/` |
| 反馈、纠错、试点记录 | `vault/logs/` |

第一版至少要跑通：

```text
真实输入 → Agent 读取上下文 → 生成结果或操作草稿 → 人工确认 → 真实用户验收
```

如果涉及发送消息、删除数据、付款、改权限或修改外部系统，Agent 默认只能生成方案，不能直接执行。

## 4. Feedback：把一次交付变成组织能力

试点过程中记录三类反馈：

- 用户纠正了什么：说明上下文、规则或 Skill 缺失。
- Agent 在哪里失败：说明适用范围、失败条件或权限边界需要补充。
- 用户实际节省了什么：记录步骤数、处理时间、返工次数或错误类型等可核验指标。

一条经验不能直接覆盖共享 Skill。推荐使用以下生命周期：

```text
draft → trial → active → deprecated
```

只有经过负责人审核、具备适用范围和验收标准的 Skill，才可以进入 `active` 状态。

## 5. FDE 交付完成的判断

一次交付至少满足以下条件：

- 有真实用户和真实输入，不只是演示数据。
- 有明确的端到端边界，不把所有问题都塞进 Agent。
- 有人工确认、失败回退和权限边界。
- 有一条可复现的配置路径，另一个人能理解如何启动。
- 有试点反馈和下一轮迭代计划。

如果只能做 Prompt 演示、不能进入现场，也没有真实用户验证，那么它还不是完整的 FDE 交付。
